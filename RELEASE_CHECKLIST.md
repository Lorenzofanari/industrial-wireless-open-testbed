# Release checklist

Steps to publish a citable release of this artifact and prepare it as
Supplementary Material for MDPI *Hardware*.

## Pre-release verification

- [ ] CI passes on the default branch
      (`.github/workflows/reproducibility.yml`: tests + demo + reproducibility).
- [ ] Local checks pass:
      ```bash
      python scripts/run_demo.py --all
      python scripts/verify_reproducibility.py --all
      pytest
      ```
- [ ] `docs/repository_submission_readiness.md` is up to date.

## Metadata

- [ ] `CITATION.cff` contains no placeholder DOI.
- [ ] `CITATION.cff` contains no release date before the GitHub release is published.
- [ ] Version `0.1.1` is consistent across `CITATION.cff`, `pyproject.toml` and
      `src/packet_observability/__init__.py`.
- [ ] `CHANGELOG.md` has an entry for the release.
- [ ] The repository URL is correct.
- [ ] The authors' names are consistent across the manuscript and repository.
- [ ] README title matches the manuscript title.
- [ ] License is present and correct (see `LICENSE`).
- [ ] Safety notes are present (`docs/safety_and_ethics.md`,
      `hardware/safety_notes.md`).

## Firewall

- [ ] No protected scheduler material is present (no cooldown-on-failure
      scheduler, π_on/p_loss/χ coefficients, ns-3 campaign, S4/S8/S9
      comparison, PDR/anti-jamming/Wi-Fi 6 validation claims). Confirm with the
      grep scan in `docs/repository_submission_readiness.md`.

## GitHub release and Zenodo archive

The procedure below was followed for `v0.1.0` (archived as Zenodo DOI
10.5281/zenodo.21347262, concept DOI 10.5281/zenodo.21347261). Repeat it for
each new tag, currently `v0.1.1`. Never move or re-create an existing tag.

- [ ] Confirm that CI passes on the release commit on `master`.
- [ ] The repository is enabled in the Zenodo GitHub integration (already done
      for `v0.1.0`; verify it is still active).
- [ ] Create the annotated tag `v0.1.1` on the verified `master` commit and push
      the branch and the tag (no force-push).
- [ ] Draft GitHub release `v0.1.1` from that tag using `RELEASE_NOTES_v0.1.1.md`.
- [ ] Confirm that the release title and notes describe the software-only
      synthetic workflow, the estimator correction, and the optional hardware
      extensions accurately.
- [ ] Publish the GitHub release (this triggers the Zenodo archival).
- [ ] Confirm that Zenodo successfully archives `v0.1.1` as a new *version* of
      the existing concept record.
- [ ] Copy the real `v0.1.1` version DOI generated by Zenodo (do not reuse the
      `v0.1.0` DOI).
- [ ] Add the real DOI (`doi:`) and actual release date (`date-released:`) to
      `CITATION.cff`, replacing the TODO comment.
- [ ] Add the `v0.1.1` DOI to the README "Citation" and "Releases" sections.
- [ ] Update the manuscript Data Availability / Supplementary Materials
      statements and the `\ArtifactVersion`, `\ArtifactCommit`, `\ArtifactDOI`
      macros (see `MANUSCRIPT_RELEASE_UPDATE.md`).
- [ ] Create a follow-up commit containing the real DOI (this commit is *after*
      the tag; the tag itself is not moved).

## Supplementary package

- [ ] Build the supplementary ZIP from the items in
      `SUPPLEMENTARY_MATERIALS_CHECKLIST.md` (exclude the local `.venv/` and the
      git-ignored `results/` outputs; reviewers regenerate them).
- [ ] Verify the manuscript references the repository URL and the DOI.

## Final

- [ ] Sanity-check the supplementary ZIP unpacks and the quickstart works from a
      clean clone.
